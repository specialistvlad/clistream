# Trust and security model

The server operator and all enrolled devices are trusted to interact with all sessions belonging to that daemon. The server decrypts and relays each stream. Keep its state under a dedicated OS user in a private directory outside every exported workspace. Tunnel destinations are numeric loopback addresses configured by the supervisor operator. Clients select an export by name.

Each device proves possession of a locally generated Ed25519 key. The two Go tools share one default key per OS account, so revoking that fingerprint disconnects both tools using it. An explicit state directory has its own identity, and each Apple installation keeps its own key. Protect the device profile directory as a credential. The Go and Apple clients store private key files with mode 0600. The Apple client uses its sandboxed Application Support directory and excludes it from backup. The private key is software-backed. Losing a device requires revocation on each server where it was enrolled.

The interactive server terminal issues signed invitations for any device. The Unix administration socket lives in the daemon’s private state directory and supports invitation issuance and device revocation. Anyone holding a valid invitation can enroll multiple keys for three minutes. Press **p** to invalidate outstanding invitations across all listening addresses. Revoking a device disconnects it and rejects its saved credentials, but a valid invitation permits a fresh enrollment. Treat the QR code, shell history, terminal scrollback and shared messages as sensitive during that window. Background startup reports the listening addresses. Scripts can explicitly request a link with `clistreamd invite`. If the server private key is compromised, stop the server, rotate its identity and enroll devices again.

**Upgrade permissions.** Previously enrolled supervisors gain permission to list and control all sessions, access their shared files and use their exported ports. Review enrolled keys with `clistreamd devices` and revoke untrusted keys before upgrading.

Activity logs contain device key fingerprints, network endpoints, session and connection IDs, operation categories, UTC timestamps and outcomes. These fields can identify a device and when it used a session. Only the state-directory owner should have access. The daemon records metadata at connection and channel boundaries. It omits keys, invitations, commands, program names, file paths and contents, terminal input and output, export names, forwarded data and peer-supplied error text. With stderr logging, access and retention depend on the collecting service. [Retention and destination](deployment.md#server-activity-logs)

## Supervisor management

An enrolled key can retrieve arguments and manage every supervisor on its daemon. The broker checks the requester and the target’s enrollment before dispatch. The broker and supervisor check the expected run and revision. An argument edit supplies individual strings to the fixed executable. The child runs with the supervisor account’s permissions and interprets its own arguments. Argument values travel through the trusted broker and stay out of listings, activity records and lifecycle errors. The Go dashboard interprets terminal escape sequences inside the child viewport, filters control characters from labels and keeps paste separate from shortcuts.

## Workspace service

The shared folder determines which files the file service presents to enrolled clients. The supervised program, including commands entered through its terminal, uses the host account's normal filesystem permissions. Services reached through port forwarding have their own access rules.

The current supervisor opens its startup working directory once as the shared folder. Directory lookup walks pinned descriptors with no-follow opens. The Linux implementation uses openat2 with BENEATH, NO_SYMLINKS and NO_XDEV. On ENOSYS it opens each single component with O_NOFOLLOW and verifies parent and child kernel mount IDs from procfs. Missing mount information fails closed. macOS also compares the device of every opened descriptor. Transfers accept regular, single-link files. Uploads stage private temporary files in the destination directory, require an explicit end record and publish with an atomic, no-replace link. An interrupted transfer removes its staging file during normal process cleanup. A supervisor crash can leave a hidden staging file that the service refuses to expose. Explicit selection of the shared folder is planned. [Session folder selection](requirements.md#session-folder-selection)

Compression runs inside encrypted QUIC and uses a fresh Snappy block for each record. This avoids a shared compression dictionary across devices, files, invitations or keystrokes. A single record can still expose its approximate compressed size. TLS negotiates its standard TLS 1.3 AEAD suite. The implementation has not undergone an independent security audit.
