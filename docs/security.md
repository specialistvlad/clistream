# Trust and security model

The server operator and all enrolled devices are trusted to interact with all sessions belonging to that daemon. The server decrypts and relays each stream. Keep its state under a dedicated OS user in a private directory outside every exported workspace. Tunnel destinations are numeric loopback addresses configured by the supervisor operator. Clients select an export by name.

Each device proves possession of a locally generated Ed25519 key. The two Go tools share one default key per OS account, so revoking that fingerprint disconnects both tools using it. Each Apple installation stores a separate device identity for each paired server. Protect the device profile directory as a credential. The Go and Apple clients store private key files with mode 0600. Each Apple app shares its enrollment directory with its signed File Provider extension through a private App Group excluded from backup. The mobile app migrates existing keys from Application Support. Camera and pasteboard input use the same signed-invitation checks as opening a link. Scanning displays the address and fingerprint for review before enrollment. The private key is software-backed. Losing a device requires revocation on each server where it was enrolled.

The interactive server terminal issues signed invitations for any device. Go clients check the visible URL host against the signed endpoint and connect using its authenticated port and server pin. The Unix administration socket lives in the daemon’s private state directory and supports invitation issuance and device revocation. Anyone holding a valid invitation can enroll multiple keys for three minutes. Press **p** to invalidate outstanding invitations across all listening addresses. Revoking a device disconnects it and rejects its saved credentials, but a valid invitation permits a fresh enrollment. Treat the visible invitation in Apple pairing sheets, QR code, shell history, terminal scrollback and shared messages as sensitive during that window. Background startup reports the listening addresses. Scripts can explicitly request a link with `clistreamd invite`. If the server private key is compromised, stop the server, rotate its identity and enroll devices again.

**Upgrade permissions.** Previously enrolled supervisors gain permission to list and control all sessions, access their shared files and use their exported ports. Review enrolled keys with `clistreamd devices` and revoke untrusted keys before upgrading.

Activity logs contain device key fingerprints, network endpoints, session and connection IDs, operation categories, UTC timestamps and outcomes. These fields can identify a device and when it used a session. Only the state-directory owner should have access. The daemon records metadata at connection and channel boundaries. It omits keys, invitations, commands, program names, file paths and contents, terminal input and output, export names, forwarded data and peer-supplied error text. Each event also goes to stderr by default. Access to that copy and its retention depend on the console or collecting service. [Retention and destination](deployment.md#server-activity-logs)

## Supervisor management

The host can select `--once` to omit remote lifecycle controls. Enrolled viewers still interact with the running program using its ordinary input, files and configured exports.

An enrolled key can retrieve arguments and manage every supervisor on its daemon. The broker checks the requester and the target’s enrollment before dispatch. The broker and supervisor check the expected run and revision. With command editing enabled, any enrolled operator can launch a different executable under the supervisor account, including a shell. The supervisor passes the submitted argument vector directly to the program. Use attach-only supervision when remote operators should have no restart control. Argument values travel through the trusted broker and stay out of listings, activity records and lifecycle errors. The Go dashboard interprets terminal escape sequences inside the child viewport, filters control characters from labels and keeps paste separate from shortcuts.

## Workspace service

The shared folder determines which files the file service presents to enrolled clients. The supervised program, including commands entered through its terminal, uses the host account's normal filesystem permissions. Services reached through port forwarding have their own access rules.

The supervisor opens the selected workspace once at launch. It defaults to the startup working directory. With `--files=FALSE`, the supervisor opens no workspace and rejects all remote file operations. Directory lookup walks pinned descriptors with no-follow opens. The Linux implementation uses openat2 with BENEATH, NO_SYMLINKS and NO_XDEV. On ENOSYS it opens each single component with O_NOFOLLOW and verifies parent and child kernel mount IDs from procfs. Missing mount information fails closed. macOS also compares the device of every opened descriptor. Transfers accept regular, single-link files. Uploads stage private temporary files in the destination directory, require an explicit end record and publish with an atomic, no-replace link on the original upload channel. The Go CLI copy operation publishes by atomic rename and can replace an existing shared file. Enrolled clients can also rename and delete entries or create and remove directories within the pinned workspace. An interrupted transfer removes its staging file during normal process cleanup. A supervisor crash can leave a hidden staging file that the service refuses to expose. [Session folder selection](requirements.md#session-folder-selection)

Compression runs inside encrypted QUIC and uses a fresh Snappy block for each record. This avoids a shared compression dictionary across devices, files, invitations or keystrokes. A single record can still expose its approximate compressed size. TLS negotiates its standard TLS 1.3 AEAD suite. The implementation has not undergone an independent security audit.

Supervisor reconnects use the saved device key and pinned broker identity. A pin mismatch or explicit authorization rejection ends retries. The supervisor header uses the client’s label and terminal-cell sanitization.

The supervisor’s default local view exposes operation metadata. The private journal is written in both display modes and excludes command arguments, names of accessed files and exports, terminal data, and peer error text. The supervisor observes the broker-facing channels and does not infer remote device identity. The child continues to run with the host account’s ordinary permissions.

Apple clients scope session selection and port forwarding to the selected server profile. The interactive attachment owns input, resize, EOF, and named forwards. The Go supervisor continues to authorize file operations independently of the Apple apps. Disable a supervisor’s workspace with `--files=FALSE`.

Apple clients identify a saved server by its pinned identity. Each additional server has a private enrollment directory. Terminal input, results, lifecycle requests and forwarding use that server’s profile. Display names are local labels. On Mac, enrollment migration preserves the existing key and server pin. Removing a Mac profile forgets it on that device. The operator can revoke its key on the daemon.

The sandboxed Mac app and Finder extension use the client and server network entitlements to send and receive QUIC datagrams. The app also listens for local port forwards. The extension uses the paired identity to connect to the pinned server. The app and extension share enrollment and provider metadata in their App Group. macOS manages downloaded documents in the local Finder domain. Revocation blocks future remote access. Copies already downloaded or saved elsewhere may remain on the Mac. [Apple network entitlements](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.network.client)
